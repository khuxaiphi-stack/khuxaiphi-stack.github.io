SPECIFICATION: CLIENT NEW USER PROVISIONING

RAW 4-MINUTE LOOM TRANSCRIPT · L3 SENIOR ENGINEER:

"Hey team, recording a quick screen share while I set up this new starter for Apex Legal so L1 stops escalating these. First thing—check the ticket in HaloPSA. Do not create an account just because an employee emailed in; check the Client Portal notes in Hudu and make sure Sarah Jenkins (their Practice Manager) approved it, and check if they're cloud-only—don't do this in M365 if they're Hybrid AD synced! Also check if they have a spare Business Premium seat in Pax8, or add one and log it for billing... Okay, once you're in their tenant via Partner Center GDAP—or CIPP—go to Active Users and add the user. Make sure you pick @apexlegal.com and NOT the .onmicrosoft.com fallback domain—somebody did that on Tuesday and broke their email routing... Keep them as a standard user, and under profile info, fill in their Job Title, Department, and Manager so their dynamic groups and signature tool pull it right. Next, wait about two minutes for the Exchange mailbox to provision—while that's spinning up, jump into Entra ID and put them in SG-All-Staff and SG-ConditionalAccess-MFA-Users. Never turn on legacy Per-User MFA! Once Exchange finishes, add them to the Reception shared mailbox with Full Access and Send As—and if it's a high-volume mailbox they don't want automapped, use PowerShell Add-MailboxPermission -AutoMapping $false. Last step, put the temp password in a 7-day OneTimeSecret link and email it to Sarah, paste the QA checklist in Halo internal notes, update billing, and close the ticket."

01 Pre-Flight Checklist (Stop & Verify in PSA First)
  • Authorized PoC Approval: Confirm written approval on the HaloPSA ticket from the client's designated PoC listed in the Hudu Client Portal.
  • Directory Sync Check: Confirm tenant is Cloud-Only. If Hybrid AD synced, STOP and route to on-prem AD onboarding SOP.
  • License Seat Check: Audit available M365 Business Premium seats in Pax8/M365. If 0, procure 1 seat and log to ticket billing.
02 Step-by-Step Execution (PII Sanitized)
Step 2.1 — User Provisioning & Directory Attributes (M365 Admin Center)
  1. Open client tenant via Partner Center (GDAP) or CIPP → Users → Active users → Add a user.
  2. Enter First/Last Name and ensure primary domain @[Client_Primary_Domain] is selected.
  3. Assign Microsoft 365 Business Premium, assign role as Standard User, and populate Job Title, Department, and Manager.
CRITICAL QA: Never leave domain dropdown on .onmicrosoft.com—breaks external mail routing and UPN identity.
Step 2.2 — Enforce Conditional Access MFA (Microsoft Entra ID)
  1. While Exchange Online provisions the mailbox (~2 mins), open Microsoft Entra Admin Center → Users → Select user → Groups.
  2. Add user to SG-All-Staff and SG-ConditionalAccess-MFA-Users. Never enable legacy Per-User MFA.
Step 2.3 — Exchange Shared Mailbox Delegation (After 2-Min Provisioning)
  1. Confirm the user's Exchange Online mailbox is active, then grant Full Access and Send As on the requested shared mailbox (e.g., [Shared_Mailbox]).
  2. For high-volume mailboxes where Outlook automapping must be suppressed, run:
Add-MailboxPermission -Identity "shared@[Client_Primary_Domain]" -User "newuser@[Client_Primary_Domain]" -AccessRights FullAccess -AutoMapping $false Add-RecipientPermission -Identity "shared@[Client_Primary_Domain]" -Trustee "newuser@[Client_Primary_Domain]" -AccessRights SendAs -Confirm:$false
Step 2.4 — Encrypted Credential Delivery
  1. Generate an expiring 7-day OneTimeSecret link containing the temporary password.
  2. Email the onboarding details + link to the Authorized PoC (never send passwords in plain-text ticket replies).
